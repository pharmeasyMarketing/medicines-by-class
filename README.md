# Medicines by Class

Static, crawlable directory of PharmEasy medicine classes, built from Google
Sheets and hydrated with live pricing in the browser.

**33 pages** – 1 directory hub + 32 class pages, from **1,413 medicines**.

```
sheets/*.csv          the source of truth (mirrors of the Google Sheets)
src/prep/             one-time: catalogue dump -> sheets
src/build.mjs         nightly: sheets -> dist/
src/snapshot.mjs      nightly: live prices -> data/prices.json
src/validate.mjs      gate: fails the build on bad sheet data
assets/               tokens.css, styles.css, app.js
deploy/               price-proxy.php (only if not on a pharmeasy.in origin)
dist/                 build output – this is what ships
```

## The Google Sheet

One spreadsheet, five tabs – [Medicines-by-class](https://docs.google.com/spreadsheets/d/1HgeXKTLWRIls3TfOjdnvUMJdW-0DE-8Pdr1hJ34pziA/edit).

| Tab | Rows | Owner |
|---|---|---|
| `classes` | 32 | SEO |
| `medicines` | 1,413 | generated from the catalogue dump |
| `content` | 33 | content + medical reviewer |
| `faqs` | 198 | content |
| `redirects` | – | SEO |

### First-time load

`Medicines-by-class.xlsx` in the repo root holds all five tabs. In the sheet:
**File → Import → Upload → select the file → "Insert new sheet(s)" → Import**.

Then delete the empty default `Sheet1`, and share the sheet
**Anyone with the link → Viewer** (the build reads it unauthenticated).

Header colours: teal = safe to edit, grey = regenerated by the pipeline on the
next catalogue refresh.

## Daily run

```bash
SHEET_ID=1Hge... node src/fetch-sheets.mjs   # tabs -> sheets/*.csv
node src/validate.mjs                        # 0 errors required
node src/snapshot.mjs                        # ~25s for 1,413 skus
node src/build.mjs                           # ~1s
```

`fetch-sheets.mjs` fetches tabs **by name**, not gid, so a tab can be deleted
and recreated without breaking the build. It refuses to overwrite a local copy
if a tab comes back with less than half the rows it had – a half-saved edit
can't wipe the site.

`.github/workflows/build-deploy.yml` does this nightly at 02:00 IST, on a
`sheet-updated` repository_dispatch, or on demand. It only rsyncs when the
content hash of at least one page changed.

## Re-running the catalogue extraction

Only when you get a fresh catalogue dump – the daily build reads the sheets,
not the dump.

```bash
python3 src/prep/extract_catalogue.py \
  --catalogue "query_result_*.csv" \
  --targets   "Navigation links - Sheet8.csv" \
  --out sheets
python3 src/prep/gen_content.py --out sheets
```

## The three data layers

| Layer | Lives in | Changes | Owner |
|---|---|---|---|
| Structure | `01_classes.csv`, `02_medicines.csv` | on catalogue refresh | SEO / catalogue |
| Content | `03_class_content.csv`, `04_faqs.csv` | on editorial review | content + medical reviewer |
| Commerce | the API, per request | constantly | not editable |

Price, MRP, discount, stock and substitute availability are **never** in the
sheets. They come from `api.pharmeasy.in/v5/product-details/{id}/dynamic`.

## Two things that will bite you

### 1. The pricing API only allows CORS from pharmeasy.in

Verified against the live API:

```
Origin: https://pharmeasy.in  ->  access-control-allow-origin: https://pharmeasy.in
Origin: https://example.com   ->  (no CORS headers – browser blocks the fetch)
```

So:

- **Served from `pharmeasy.in/medicines-by-class/`** → call the API directly.
  Set `PUBLIC_PRICE_API` to the api.pharmeasy.in template. This is the option
  worth fighting for, and not only for pricing – a directory on the main
  domain is the whole SEO case for this project.
- **Served from any other host** → deploy `deploy/price-proxy.php` and set
  `PUBLIC_PRICE_API=/medicines-by-class/price-proxy.php?id={id}`. It presents a
  pharmeasy.in Origin upstream, caches 60s on disk, and serves stale on
  upstream failure.

Either way the page still renders: every card ships with a build-time price
baked into the HTML, so a blocked or failed fetch leaves the last known price
on screen rather than blanking the grid.

### 2. Prices in the HTML are a snapshot, not the transactable price

The snapshot exists so crawlers see real numbers and so there is no layout
shift. Guardrails already in the code:

- `src/snapshot.mjs` aborts if more than 20% of lookups fail, rather than
  writing a mostly-empty snapshot.
- The browser always re-fetches and overwrites in place.
- Cards whose live call says unavailable get a disabled button reading
  "Currently unavailable" – a stale price is never transactable.

Given PharmEasy publishes a Declaration on Dark Patterns, the snapshot must
stay a display convenience. Keep the nightly cadence so it is never more than
24h old.

## What the data showed

- **1,716 target URLs → 1,457 usable.** 249 discontinued and 9 banned were
  dropped; they are excluded from browse grids on compliance grounds even
  though their PDPs still return 200.
- **`is_live=false` does not mean delisted.** Verified: those PDPs return 200
  and the API returns a real price – they are out of stock, not gone. They are
  kept, with availability driven by the live call. Filtering them out would
  have silently deleted the entire Mental Health class (138 of 139 products
  are Schedule H and flagged not-live).
- **8 classes fell below the 8-product threshold** and are not published:
  Immunosuppressants, Eye and Ear, Kidney and Urology, Antiparasitic, Sleep
  Aid, Tuberculosis, Local Anaesthetics, Thyroid. Raise
  `MIN_PRODUCTS_FOR_PAGE` in `src/prep/taxonomy.py` or add products to publish
  them.
- **Sub-classes are derived, not hand-maintained.** Molecule names map to
  pharmacological groups (Metformin → Biguanides, `*gliptin` → DPP-4
  inhibitors, Tirzepatide/Semaglutide → GLP-1 receptor agonists). Classes
  built from several clinical tags use the tags instead.

## Content status

All 32 classes have draft copy, written to the design's rule: "used for" /
"used in the management of", never "cures" or "treats". `src/validate.mjs`
fails the build on promissory claims and on any class marked `published`
without a named reviewer.

Nothing is review-signed yet. To publish a class: fill `reviewer_name` and
`reviewer_credentials` in `03_class_content.csv` and set
`content_status=published`.

## Typography and colour

Taken from the **live pharmeasy.in stylesheet**, not from the design-system
reconstruction. Where they disagreed, production won:

| | Design system said | Live site is |
|---|---|---|
| Font | Mulish (Google Fonts) | **Inter**, self-hosted `Inter-subset.woff2`, variable **400–700** |
| Primary | `#008880` (sampled from logo) | **`#10847e`** |
| Text | `#25282B` / `#5C636D` / `#8E97A3` | `#30363c` / `#4f585e` / `#8897a2` |
| Page bg | `#F5F7F8` | `#f4f7fb` |

The Inter subset has **no weight above 700**. Every `font-weight: 800` was
removed – the browser was synthesising a fake bold that does not exist on the
live site. Type scale now follows the live one: 14px body, 12/13/16 supporting,
18/22/26/30 headings.

## Header

Single teal bar. Delivery-location, login and offers are gone; the primary nav
that had its own white row now sits inline with the logo, and cart is the only
account control. The production logo is teal-on-transparent, so it is knocked
to white with `filter: brightness(0) invert(1)` rather than shipping a second
asset.

## Cart

Items live in `localStorage` (`pe_mbc_cart`) and the header count reflects them.
The cart link carries the skus across for the real cart to rehydrate:

    https://pharmeasy.in/cart?src=header&items=49203,49202

**The `items=` parameter is an assumption.** pharmeasy.in/cart has to be able to
read it, which needs confirming with whoever owns the cart. Until then the link
still opens the real cart, it just arrives empty.

## The extra 15%

`CFG.extraOffPct` (default 15) is applied on top of the API sale price, in both
the build and the browser, so the number never changes between them. The
discount badge and "you save" are recalculated against MRP, and a small T&C
link sits next to both the badge and the price.

Set `EXTRA_OFF_PCT=0` to switch it off everywhere in one place if the offer ends.

## Condition search

`conditions` on the classes tab holds pipe-separated everyday words –
`fever|body pain|headache|...`. These feed both the directory search and a
"best match" banner, so someone typing *fever* lands on Pain Relief and
*acidity* on Gastrointestinal, even though neither word appears in a class name.
236 terms seeded across 32 classes; edit the column to tune.

## Schema

One `@graph` per page rather than loose blocks, so `Organization` and `WebSite`
resolve to a single node by `@id`:

| Node | Where | Why |
|---|---|---|
| `Organization` + `MedicalBusiness` | both | publisher identity |
| `WebSite` + `SearchAction` | both | sitelinks searchbox |
| `MedicalWebPage` | both | carries **`lastReviewed`** + **`reviewedBy`** – the pair Google documents for health content |
| `DrugClass` | class | names the class as a medical entity |
| `MedicalCondition` × up to 12 | class | ties condition queries to the page |
| `BreadcrumbList` | both | |
| `ItemList` | both | 32 classes / all medicines |
| `FAQPage` | both | |

Deliberately **not** added: `Product`/`Offer` per medicine. Price and stock are
client-side, so the markup would frequently disagree with what Google renders –
and a mismatch on price is a rich-result penalty. That markup belongs on the PDP.

## Deviations from the design

- **No pagination.** The design specified 12 per page. Sub-class counts are
  class-wide, so a chip reading "GLP-1 receptor agonists (26)" would have
  shown 0 results on a 24-item page. All medicines now ship in the HTML and
  the browser reveals 24 at a time. Largest page (Cancer, 219) is 29KB
  gzipped.
- **The logo's "Take it easy" tagline is not repeated** – the production
  `logo_big.svg` already contains it.
- **Dosage-form pills and availability checkboxes are functional.** The design
  drew them as static spans; a dead filter reads as broken.
- **Mobile sort/filter bottom sheets were added.** The design showed the
  buttons but not the sheets.

## Config

Build-time env vars (all optional, defaults shown):

```
SITE_ORIGIN=https://pharmeasy.in
SITE_BASE=/medicines-by-class
ASSET_BASE=/medicines-by-class/assets
PRICE_API=https://api.pharmeasy.in/v5/product-details/{id}/dynamic   # snapshot

```

Repo **variable**: `SHEET_ID` (the spreadsheet id from the sheet URL).
Repo **secrets**: `DEPLOY_SSH_KEY`, `DEPLOY_HOST`, `DEPLOY_USER`,
`DEPLOY_PATH`, `DEPLOY_KNOWN_HOSTS`.

### Rebuild on every sheet edit

Bind this to the sheet (Extensions → Apps Script) and add an installable
`On change` trigger. `GH_TOKEN` needs only `repo` scope.

```js
function onSheetChange() {
  UrlFetchApp.fetch('https://api.github.com/repos/OWNER/REPO/dispatches', {
    method: 'post',
    contentType: 'application/json',
    headers: { Authorization: 'Bearer ' + PropertiesService
      .getScriptProperties().getProperty('GH_TOKEN') },
    payload: JSON.stringify({ event_type: 'sheet-updated' })
  });
}
```
